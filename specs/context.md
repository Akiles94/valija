# Spec: context — the saved-content bounded context

Content subdomain. Ubiquitous language: **project, context item, type, tag, pinned, archived**. Depends on `shared`, and on `vault` only through the session bridge.

## domain/errors.ts

`INVALID_PROJECT_NAME · INVALID_ITEM_TYPE · INVALID_TAG · CONTENT_TOO_LARGE · CONTENT_EMPTY · TOO_MANY_TAGS · PROJECT_NOT_FOUND · ITEM_NOT_FOUND · INVALID_ITEM_ID · ITEM_ID_AMBIGUOUS · ITEM_ARCHIVED · ITEM_PINNED · ITEM_NOT_CURATABLE · NOTHING_TO_EDIT · PROJECT_NOT_DETECTED · PROJECT_AMBIGUOUS · BINDING_CONFLICT · BINDING_NOT_FOUND · NO_GIT_REMOTE · INVALID_WORKSPACE_PATH · POSSIBLE_SECRET`

`POSSIBLE_SECRET` (SECRET-WARN) follows a stricter one: its message names secret **kinds**, **line numbers** and chunk counts only — **never** matched text, a prefix, a suffix, a mask or a length. The message is surface-neutral; each delivery surface appends its own remedy.

The six PROJECT-DETECT codes follow one invariant: a message may name project slugs, binding ids and a binding *kind*, and **never a path, a remote, or the raw input** (a raw remote can carry a token). Surfaces show targets from DTO fields, never from error text.

## domain/values (parse-don't-validate; branded types)

- **ProjectName** — `[a-z0-9][a-z0-9-]{0,63}`, trimmed + lowercased. Violation → `INVALID_PROJECT_NAME`.
- **ItemType** — one of `decision | progress | preference | fact | handoff`. Else → `INVALID_ITEM_TYPE`. **StorableItemType** adds `imported` (the six types that may be *stored*); `parseStorableItemType` accepts it, `parseItemType` does not. The split keeps `imported` off the save/MCP surface (`ITEM_TYPES` is the MCP enum) while letting storage and reads carry it.
- **Tag** — 1–32 chars of `[a-z0-9-]`, trimmed + lowercased. Max 10 (`TOO_MANY_TAGS`), duplicates dropped.
- **Content** — trimmed; empty → `CONTENT_EMPTY`; over **32 KB in UTF-8 bytes** → `CONTENT_TOO_LARGE`; exactly 32 KB accepted.
- **ItemId** — 1–64 chars of `[A-Za-z0-9-]`, trimmed, case kept (ULIDs, `imp-<hex>` and fixture ids all fit; never assumed to be a ULID). Else → `INVALID_ITEM_ID`. The charset excludes `%`/`_`, so a parsed id can never be a `LIKE` wildcard. **ItemReference** — an `ItemId` of at least 6 chars: a full id or a unique prefix (CURATION D-I).
- **BindingKind** — `folder | repository` (`BINDING_KINDS`). Validated at each surface's own boundary (commander `.choices()`, `z.enum`), so there is no domain parser (PROJECT-DETECT P-13).
- **FolderTarget** (`binding-target.ts`) — a canonical absolute directory path. `parseFolderTarget(raw, platform?)` trims, requires an absolute path for `platform`, strips trailing separators except on a root, and upper-cases a Windows drive letter; else → `INVALID_WORKSPACE_PATH` (input never echoed). `folderDepth` counts non-empty segments (split on `/` and `\`), used to rank folder bindings. The same file defines **WorkspaceLocation** `{ folder, repositoryRoot, repository, tooBroadToLink }` — where work is happening, as the probe reports it.
- **RepositoryTarget** (`repository-target.ts`, D-K) — a normalized remote, `host/owner/repo`. `parseRepositoryTarget` accepts the URL form (`ssh`, `git+ssh`, `ssh+git`, `git`, `http`, `https`; only `hostname` is read, so userinfo and port are dropped by construction) and the scp form (`[user@]host:path`, host ≥ 2 chars so `C:\repo` is not one); local paths and `file://` are not usable (P-5). The host is lower-cased and must be `[a-z0-9.-]`; the path drops a leading `/` or `~/`, repeated and trailing `/`, and a trailing `.git`; path case is kept. Path segments are read from the raw string (a `URL` would resolve `..` silently) and must be `[A-Za-z0-9._~%-]`, with no `.`/`..` — so no `@`, `:`, `?` or `#` (nothing credential-shaped) can survive. Any rejection → `NO_GIT_REMOTE` with one fixed sentence; the input is never echoed. `repositoryName` is the last segment.
- **SecretFinding** (`secret-finding.ts`, SECRET-WARN) — `{ kind, firstLine, lastLine }` (1-based; `lastLine` differs only for multi-line private-key blocks). By design there is **no field that could hold matched text**. `SECRET_KINDS` is the closed, precedence-ordered 12-kind enum (`private-key`, `aws-access-key`, `github-token`, `anthropic-api-key`, `openai-api-key`, `slack-token`, `stripe-secret-key`, `google-api-key`, `jwt`, `url-credentials`, `credential-assignment`, `high-entropy-string`); `SECRET_KIND_LABELS` holds the English mid-sentence labels used by CLI and MCP (product names keep their case); `isSecretKind` narrows a wire string. `describeFindings(findings, cap = 5)` renders `GitHub token (line 7), private key (lines 12–40)`, sorted by line then precedence, capped with `, and N more`.
- **BindingId** — same grammar as `ItemId`; a malformed id → `BINDING_NOT_FOUND` (it cannot match a row, so "not found" is the honest answer).

## domain/entities

- **Project**: id, name, description?, timestamps.
- **ProjectBinding** (PROJECT-DETECT): id, projectId, kind (`BindingKind`), target (`FolderTarget | RepositoryTarget`), createdAt — a user-made link from a folder or repository to one project. Minted by the total `createProjectBinding`.
- **ContextItem**: id, projectId, type (`StorableItemType`), content, tags, pinned, source?, archived, timestamps. Minted via `createContextItem` (the five saveable types) or `createImportedContextItem` — both total. The imported factory fixes `type: imported`, is never pinned, keeps the **original conversation date** as `createdAt` while stamping `updatedAt` at the import instant, sets `source: "<src>-import"`, and derives a **deterministic id** (`importedItemId(projectId, source, conversationId, chunkIndex)`), so re-importing the same export into the same project upserts instead of duplicating, while the same conversation imported into a different project stays distinct.

## domain/services

- `context-pack.ts` — **the assembly algorithm**, pure and vault-free. `assembleContextPack({ projectName, items, generatedAt, budgetTokens? })`; tokens ≈ `ceil(chars/4)`. Order: (1) **pinned** newest-first — the newest pinned is kept even if it alone exceeds budget, oldest pinned cut first; (2) **latest handoff** if it fits; (3) a section per type, **decision → preference → progress → fact**, newest-first, until one doesn't fit. No item repeats. Omitting `budgetTokens` (or passing `Infinity`) means unbudgeted. Returns sections carrying **entities, not text** — `estimatedTokens` is the sum of the domain's estimates, so it is an approximation of the rendered result, never a promise about it.
- `item-curation.ts` — **the curation rules** (CURATION), pure functions taking `now`: `setPinned`, `setArchived` (total), `applyEdit`, `archiveSuperseded`. Each reports whether anything changed, so a no-op is never persisted. Pin, edit and supersede refuse imported items (`ITEM_NOT_CURATABLE`) and archived ones (`ITEM_ARCHIVED`) — rejections are checked before no-ops; unpin and archive/unarchive work on anything. Archive never touches `pinned`. `archiveSuperseded` also refuses a pinned item (`ITEM_PINNED` — a pin is the user's call).
- `project-resolution.ts` — **the detection rules** (PROJECT-DETECT D-E/D-K/D-L), pure, taking an optional `platform`. It never sees `VALIJA_PROJECT` or an explicit name; callers rank those first. `BoundProject { binding, projectName }` is what a binding list yields. `bindingFor(location, bindings)` — the deepest folder binding covering the location (containment and case rule from `shared/domain/services/path-containment.ts`), else the repository binding whose target equals `location.repository`, else `null`. `resolveFromBindings(locations, bindings)` — maps every location through `bindingFor`; unmatched locations are ignored; one distinct project → `bound`, two or more → `ambiguous` with slugs sorted, none → `none`. `bindingOnTarget(bindings, kind, target)` — the binding that owns that exact target (folders compared both ways with `isSameOrInside`, so case-folding agrees with matching). `chooseLinkTarget(location, by?)` — the repository when it has a usable remote, else the folder; `by: "repository"` without one → `NO_GIT_REMOTE`; a folder link on a `tooBroadToLink` location (home or filesystem root) → `INVALID_WORKSPACE_PATH` (P-4). `hintCandidates(location)` — the repository's name and its root folder's name, lower-cased and de-duplicated; `[]` outside a repository. It only ever feeds a hint, never a routing decision.

- `secret-detection/` (SECRET-WARN) — **the secret detector**, a feature folder of pure functions. **Node-free** (no `node:` import, no `Buffer`, no `process`; a guard test enforces it), because the desktop renderer bundles it to describe an Edit refusal.
  - `detect-secrets.ts` — `detectSecrets(text) → SecretFinding[]`. Splits on `\r?\n` (CRLF and LF number lines alike), runs every tier's rule, and keeps **one finding per span**: a match is dropped when a higher-precedence match overlaps it (same lines and overlapping columns; a multi-line block overlaps everything on its lines). Precedence is tier 1 → tier 2 → tier 3, and inside tier 1 the `SECRET_KINDS` order (so an `sk-ant-…` key is `anthropic-api-key` only). Findings are de-duplicated by `(kind, firstLine, lastLine)` and sorted by line.
  - `secret-match.ts` — the internal `SecretMatch` (finding + column span), `WHOLE_LINE`, `tierOf`. Never leaves the folder.
  - `placeholder.ts` — `isPlaceholder(value)`, the exclusions common to every tier: a template marker (`<…>`, `${…}`, `{{…}}`, `%VAR%` anywhere, or `$VAR` as the whole value); a run of one repeated character; or one of the words `example`, `placeholder`, `redacted`, `changeme`, `dummy`, `sample`, `your_`, `your-` (case-insensitive — this also covers AWS's documented `…EXAMPLE` keys).
  - `known-formats.ts` — **tier 1**, `findKnownFormats(lines)`. Single-line shapes, each anchored on a literal prefix with a realistic minimum length, so prose that merely names a prefix stays silent: AWS access-key ids (`AKIA`/`ASIA` + 16), GitHub tokens (`gh[pousr]_` + 36, `github_pat_` + ≥ 22), Anthropic keys (`sk-ant-` + ≥ 32), OpenAI keys (`sk-` / `sk-proj-` + ≥ 32, never `sk-ant-`), Slack tokens (`xox[abprs]-` + ≥ 10), Stripe secret keys (`sk_live_`, `rk_live_`, `sk_test_` + ≥ 16), Google API keys (`AIza` + 35), and JWTs (structural only: an `eyJ` header and three base64url segments of ≥ 8). A token that is a placeholder, or contains a mask (eight of one character in a row), is skipped. **`url-credentials`**: `scheme://user:password@` where the password is not a placeholder, not `password`/`pass`/`secret`/`changeme`, and not `*`-masked; the groups are read in memory and never stored. **`private-key`**: a PEM/OpenSSH/PGP **private** key header followed, within 4 lines (or on the same line, for a key pasted with escaped newlines), by a base64 body line of ≥ 32 characters that is not pure hex (a git SHA or digest after a header mentioned in prose is not key material); it spans header through the `-----END …-----` line, or through the last body line. A bare header in prose, public keys and certificates never fire.
  - `credential-assignment.ts` — **tier 2**, `findCredentialAssignments(lines)`: a **key, an operator and a value on one line**. The key is an identifier (optionally quoted, optionally after `export `) whose normalized form (lower-cased, `_` `-` `.` removed) **ends with** `password`, `passwd`, `secret`, `clientsecret`, `secretkey`, `apikey`, `accesskey`, `accesstoken`, `authtoken`, `refreshtoken`, `token` or `privatekey` — so a key that merely *starts* with one of them (a policy, a tokenizer, a token budget) is silent, and `pwd` / `pass` are not keys. The operator is `=`, `:`, `:=` or `=>`. The value is a quoted string with no whitespace, or one unquoted token ending at whitespace, a quote, or `,` `;` `}` `#` (a quote closing a surrounding code string literal is skipped); **a value followed by more words does not fire** (that keeps prose silent). The value must then look like a credential: at least 8 characters; at least 2 of {lowercase, uppercase, digit, symbol}, or at least 16 characters; not a placeholder and not `null`/`none`/`nil`/`undefined`/`true`/`false`/`string`/`number`; no parentheses (a call); not a dotted path (a config or environment reference); not starting with `$`, `env(` or `secrets.`; not an unquoted run of letters and `_` only (a code identifier); not starting with `/`, `./` or `~/` (a path). The match spans the **value's** columns, so a tier-1 token used as the value is reported as tier 1 only.
  - `high-entropy-string.ts` — **tier 3**, `findHighEntropyStrings(lines)` and `shannonEntropy(token)`. Each line is tokenized into maximal runs of `[A-Za-z0-9+/=_-]` (one linear scan). A token fires when it is **32 to 200 characters** long (longer runs are treated as encoded payloads), has **at least 2 uppercase letters, 2 lowercase letters and 2 digits**, has a Shannon entropy over its own character frequencies of **at least 4.3 bits per character**, and no exclusion explains it: pure hex of any length or case, optionally after a short lowercase prefix (git SHAs, sha256/md5 values, `imp-<hex>` ids, hex dumps — hex secrets are left to tiers 1–2); a UUID, or a ULID segment; an SRI hash (`sha256-` / `sha384-` / `sha512-`); a token right after `data:<mime>;base64,`; a hash word earlier on the line (`sha`, `sha1`, `sha256`, `sha512`, `md5`, `hash`, `digest`, `checksum`, `integrity`, `etag`, `commit`, `fingerprint`); a token inside a `scheme://…` span; a token starting with `/` (the tokenizer drops `.` and `~`, so `./`, `../` and `~/` paths arrive that way); a slash-separated path with two or more `/` and no random-looking segment; a token right after an OpenSSH public-key algorithm name (`ssh-ed25519`, `ssh-rsa`, `ssh-dss`, `ecdsa-sha2-nistp256/384/521`, `sk-…@openssh.com`); any token on a line inside a public armored block (`CERTIFICATE`, `CERTIFICATE REQUEST`, `X509 CRL`, `PUBLIC KEY`, `RSA PUBLIC KEY`, `PGP PUBLIC KEY BLOCK`, `PGP SIGNATURE`, `SSH2 PUBLIC KEY`), from its header through its `-----END …-----` line or the first line that is not base64, blank or a `Key: value` armor header; a placeholder. A token that a tier-1 or tier-2 match overlaps is dropped by precedence.
  - **Thresholds (final, SECRET-WARN):** `MIN_TOKEN_LENGTH = 32`, `MAX_TOKEN_LENGTH = 200`, `MIN_ENTROPY_BITS = 4.3` — the §8.3 initial values, unchanged after tuning. They are code constants, never settings: moving one is a code change made only while the tier-2 and tier-3 corpora and the three whole-document negatives (`docs/SPEC.md`, the golden `expected-pack.md`, a `package-lock.json` excerpt) stay green, and is recorded here.
  - **Best effort, not a guarantee.** The detector recognizes known formats, credential assignments and random-looking strings. Hex secrets outside an assignment, short passwords in prose, a key split across two import chunks, and anything saved before SECRET-WARN pass silently.
  - `secret-refusal.ts` — the policy the use cases call: `refusePossibleSecrets(content)` → `ok` or `POSSIBLE_SECRET` ("The content looks like it contains a secret — <describeFindings>. Nothing was saved."); `refuseFlaggedImport(contents)` → all-or-nothing, `importRefusedMessage(n)` ("Import refused: n chunk(s) look like they contain secrets. Nothing was imported.").
  - **ReDoS rule:** every quantifier on a character class is bounded (`{m,n}`); lines are scanned one at a time.

## application/ports

- `repositories.ts` — `ProjectRepository` (upsert, findByName, list with counts) and `ContextItemRepository` (upsert, findById / findByIdPrefix — vault-wide, archived included, each returning an `ItemWithProject`; findByProject newest-first with filters, FTS search). There is no separate archive write: archiving is an upsert of the archived item, so it goes through the one write path that stamps `updatedAt` and the lineage. `ProjectBindingRepository` (PROJECT-DETECT): `add` is insert-only and returns `false` when the `(kind, target)` pair is taken (the caller turns that into `BINDING_CONFLICT`); `remove(bindingId)` returns `false` when no row had that id; `list()` returns every binding as a `BoundProject` (binding + project slug), ordered by project, kind, target.
- `vault-session.ts` — **the bridge**: `VaultSessions.withSession(action)` runs `action` against a `VaultSession` (`projects`, `items`, and `bindings`), or returns `VAULT_LOCKED`. The port owns the open → work → always-close lifecycle, so use cases never touch it. `VaultSession` also carries `write<T>(mutate)` (M3): runs `mutate` and, only on success, atomically stamps the vault's lineage (bump the generation, mint a fresh write stamp) as part of the same commit — the seam that lets the write path advance BYO-cloud sync's fork-detection stamp without `context` importing anything from `vault`'s storage layer. Read-only use cases never call it.
- `workspace-probe.ts` — `WorkspaceProbe.locate(directory)` (PROJECT-DETECT) → `WorkspaceLocation` (canonical folder, enclosing repository root, its normalized remote, `tooBroadToLink`) or `INVALID_WORKSPACE_PATH`. Read-only: never writes, never spawns a process, never touches the network. Use-case tests use `FakeWorkspaceProbe` (`src/testing/`), which records every directory it was asked about.

## application/services

- `item-curation-steps.ts` — stateless helpers the curation use cases share, so no use case calls another: `findItemByReference(session, ref)` (exact id first, else a unique prefix; 0 matches → `ITEM_NOT_FOUND`, 2+ → `ITEM_ID_AMBIGUOUS` listing up to 5 ids; archived items are found) and `saveIfChanged(session, item, changed)` (a no-op never opens `session.write`, so it never bumps the lineage — CURATION D-L).

## application/dto

- `context-item-view.ts` — `ContextItemView`, the one shape every read use case returns: primitives only, no value objects and no `Date`. Carries `source` so an export loses nothing. `archived` is present **only when true** (only `ShowProject` with `includeArchived` can return such an item), so every live view and every export stays byte-identical.
- `item-curation-output.ts` — `ItemCurationOutput { itemId, project, type, changed }` and `EditItemOutput` (+ `changedFields`). `changed: false` means nothing was written.
- `project-binding-view.ts` (PROJECT-DETECT) — `ProjectBindingView { id, project, kind, target, createdAt }`, primitives only; `toProjectBindingView(bound)`. `target` is a folder path or a normalized remote: the CLI and desktop may show it, the MCP adapter never reads it.
- `project-resolution-output.ts` (PROJECT-DETECT) — `DetectionKind = folder | repository | env`; `WorkspaceLocationView { folder, repositoryRoot, repository, tooBroadToLink }` (`toWorkspaceLocationView`); `ProjectResolutionOutput` = `detected { project, detectedBy, binding?, locations }` (no `binding` when `VALIJA_PROJECT` decided) · `none { hint?, locations }` · `ambiguous { projects, locations }`. `locations` exist for `which` and the desktop inspect panel only.

## application use cases

Each implements `UseCase<In, Out>` (or `AsyncUseCase`) from `shared/application/use-case.ts` — a contract, never a base class.

**SaveContext** — parses project/type(default `fact`)/tags/content **before opening a session**, so bad input never touches the vault; right after the size cap it runs `refusePossibleSecrets` on the raw input (so line numbers match what the caller sent) and refuses with `POSSIBLE_SECRET` — **there is no override input** (SECRET-WARN D-N), so an AI tool can never save a possible secret, and a refusal opens no session, creates no project, archives no `supersedes` target and bumps nothing (a locked vault plus a secret answers `POSSIBLE_SECRET`; plus clean content, `VAULT_LOCKED`); **auto-creates the project** (D9), reports `projectCreated`; captures optional `source` (MCP client name). The project find-or-create and the item save run inside `session.write(...)` (M3), so one save bumps the vault's lineage once. **`supersedes`** (CURATION, exact id only): inside that same write it checks the target first — missing or in another project → `ITEM_NOT_FOUND` with one message for both, so nothing leaks about other projects; then `archiveSuperseded` — then saves the new item and the archived old one. Any refusal rolls the whole write back, project auto-creation included; `supersededItemId` is reported only when used.

**GetContextPack({ project, budgetTokens = 4000 })** — unknown project → `PROJECT_NOT_FOUND`. Loads the project's items and delegates to `assembleContextPack`; returns the pack **structure**. Pass `Infinity` for the whole project — that is how `export` gets an unbudgeted pack.

**SearchContext** — unknown project scope → `PROJECT_NOT_FOUND`; limit clamped [1,100] default 20; empty/whitespace query → empty (terms quoted, never an FTS syntax error).

**ListProjects / ShowProject** — list with counts (archived excluded); show newest-first with optional type filter (`ShowProject` accepts `imported` via `parseStorableItemType`, so `show <p> --type imported` works). Both return `ContextItemView[]`. `ShowProject` also takes `includeArchived` (CURATION D-D): archived items are then included, each marked `archived: true`.

**SetItemPinned / SetItemArchived / EditItem** (CURATION) — the human curation verbs. Each parses an item reference (a full id or a unique ≥6-char prefix) — and, for `EditItem`, the new content/tags/type, with `NOTHING_TO_EDIT` when none is given — **before** opening a session, finds the item with `findItemByReference`, applies the `item-curation.ts` rule, and persists through `saveIfChanged`. Edit is in place: same id, `createdAt` kept, `updatedAt` stamped, FTS re-indexed by the `items_au` trigger; `tags: []` clears the tags. `EditItem` also takes `allowSecrets?` (a human's explicit override: CLI `--allow-secrets`, desktop **Save anyway**): without it, new content that looks like a secret is refused with `POSSIBLE_SECRET` before the session. Only given content is scanned — a tags-only or type-only edit never is — and re-submitted unchanged content is scanned again (D-I).

**ImportItems** — the batch write path used by the importers module. Parses the project name **before** opening a session, find-or-creates the project, then in **one session, one `session.write(...)` (M3)** re-validates each chunk's tags and content (defense in depth), mints an imported item via `createImportedContextItem`, and upserts it — keeping the chunk archived if the user archived it (CURATION D-H) — so one import bumps the vault's lineage once, not per item. A single bad chunk is collected into `failures` (never aborts the batch). Before the session, unless `allowSecrets?` is set, `refuseFlaggedImport` refuses the **whole batch** with `POSSIBLE_SECRET` when any chunk looks like it contains a secret (SECRET-WARN D-E, defense in depth: `ImportConversations` already refuses before calling it), so a refused import writes zero chunks and creates no project. Returns `{ projectCreated, imported, failed, failures }`. This keeps `context` the sole guardian of `ContextItem` and the `imported` type — importers hand it drafts, nothing more.

**Imported items and the pack:** `assembleContextPack` only ever includes pinned items, the latest handoff, and the four section types. Imported items are never pinned and are none of those types, so they are **automatically excluded** from every pack — searchable via FTS, but never auto-loaded through `get_context`.

**ResolveProject({ directories, envProject? })** (PROJECT-DETECT) — parses `envProject` (`VALIJA_PROJECT`; blank = unset; a bad value → `INVALID_PROJECT_NAME` naming the variable, never echoing it) **before** the session, then always opens the session first — so a locked vault is `VAULT_LOCKED` before any directory is probed, `VALIJA_PROJECT` or not — then probes the directories. **`VALIJA_PROJECT` beats bindings** and is not checked for existence (it behaves like an explicit name downstream); with it set, an unreadable directory is skipped rather than fatal (it cannot change the outcome), and `locations` lists the readable ones. Without it, the first unreadable directory → `INVALID_WORKSPACE_PATH`; otherwise `resolveFromBindings`. On `none`, the first `hintCandidates` name that is an *existing* project becomes `hint` — a read, never a create. No directories and no env → `none`. Read-only: never bumps the lineage.

**LinkWorkspace({ project, directory, by? })** (PROJECT-DETECT) — parses the slug before the session, then checks, in this order: the project exists (`PROJECT_NOT_FOUND`; linking never creates one), the path (`INVALID_WORKSPACE_PATH`, including home/root as a folder link), the remote (`chooseLinkTarget`: `NO_GIT_REMOTE` for `by: repository` without one), and an existing binding on that target (`bindingOnTarget`): same project → `{ changed: false }` with **no write**; another project → `BINDING_CONFLICT` naming that project's slug and the binding id. Only then one `session.write` adds the binding (one lineage bump); a lost race (`add` → `false`) is an `err`, so the write rolls back unbumped. Returns `{ binding: ProjectBindingView, changed }`.

**UnlinkWorkspace({ bindingId } | { directory, by? })** (PROJECT-DETECT) — a union, so an id and a directory can never both arrive. By id: `parseBindingId` before the session, then the binding in `session.bindings.list()`. By directory: probe it in the session, then `bindingFor` over the bindings of kind `by` (all kinds when omitted) — which can be an ancestor's folder binding or the repository's (W3). Nothing found → `BINDING_NOT_FOUND`, zero bumps. One `session.write` removes it; returns the removed `ProjectBindingView`, so a surface always names what went.

**ListProjectBindings({ project? })** (PROJECT-DETECT) — every binding, or one project's (slug parsed before the session; unknown → `PROJECT_NOT_FOUND`), as `ProjectBindingView[]` ordered by project, kind, target. Read-only.

No use case calls another: `which`, `show`/`export` detection and the MCP surface compose `ResolveProject` with the existing use cases in delivery (D-O).

There is no ExportPack use case: exporting is a rendering choice over these two, made in `delivery`.

## infra

- `project-repo.ts`, `item-repo.ts` — SQLite implementations; dates as ISO strings, tags as JSON; FTS terms individually double-quoted and ANDed, ranked by `rank`.
- `sqlite-project-binding-repository.ts` — `SqliteProjectBindingRepository` (PROJECT-DETECT) over `project_bindings`. `add` is `INSERT … ON CONFLICT(kind, target) DO NOTHING`, so a concurrent insert from another process is a clean `false`, never a throw out of `session.write`; `list` joins `projects` for the slug. All values are bound parameters.
- `file-workspace-probe.ts` — `FileWorkspaceProbe` (PROJECT-DETECT, D-J; `home` and `platform` injectable). `realpathSync.native` + `isDirectory()` → `parseFolderTarget`; any failure → `INVALID_WORKSPACE_PATH` with a fixed sentence (no path). Walks up for `.git` (≤ 64 levels, stops at the root): a directory, or a `.git` file (`gitdir: …`, worktrees and submodules, ≤ 4 KB) resolved against its folder; a malformed or symlinked `.git` marks the repository root with no remote. Worktrees follow `commondir`. Reads `config` only if it is a regular file ≤ 256 KB, picks the remote with `chooseRemote`, and hands the raw URL straight to `parseRepositoryTarget` — it is never stored, returned or logged. `tooBroadToLink` is the filesystem root or the (canonical) home folder itself (P-4). Imports `node:fs`, `node:path`, `node:os` only.
- `git/git-config.ts` — pure parser: `remoteUrls(text)` (`[remote "name"]` sections, section name case-insensitive, subsection case-sensitive, first `url` wins, comments and quotes stripped) and `chooseRemote` (D-K: `origin`, else the only remote, else none). **Limitation (D-J):** `include`/`includeIf` and `url.<base>.insteadOf` are not honoured, so a repository cannot steer which files valija reads.
- `vault-sessions.ts` — implements `VaultSessions`; the one place `context` touches `vault` (keychain + header + lineage). No keychain key → `VAULT_LOCKED`; stale key → delete it, then `VAULT_LOCKED`. On open, also consults the injected `SessionGuard` (M3 idle auto-lock — see [vault.md](vault.md)) right after the keychain check. `runWithSession` holds the always-close guarantee. `write()` (M3) runs the mutation inside the db transaction and bumps the lineage only on success (a failed `Result` throws a private sentinel to force a rollback, caught outside and unwrapped back to the original error) — last-seen is recorded only after the transaction actually commits.
