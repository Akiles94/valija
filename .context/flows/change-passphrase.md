# Flow: change-passphrase
Summary: CLI `valija change-passphrase` / desktop `vault:changePassphrase` → every precondition before any write (header, settled folder, new passphrase, current credential proven read-only, schema not newer, key really changes, cloud confirmation) → `SqliteVaultRekeyer` (space, exclusive lock, lineage bump, fsynced backup, salt-preserving raw-key `PRAGMA rekey`, fresh-connection verify, delete backup) → new key into the keychain → new recovery kit once.
Trigger: `src/delivery/cli/build-program.ts:buildProgram()` command `change-passphrase` → `src/delivery/cli/change-passphrase-command.ts:changePassphraseCommand()`; desktop IPC `vault:changePassphrase` in `desktop/src/main/ipc/handlers/vault-handlers.ts:createVaultHandlers()`, from `desktop/src/renderer/screens/change-passphrase.tsx:ChangePassphraseScreen()` (an overlay, `desktop/src/renderer/state/overlay-nav.ts:openChangePassphrase()`).
Path:
1. Surface asks first: preamble, then (cloud folder only, `VaultFolder.inspect().looksLikeCloud`) the other-devices confirmation BEFORE any credential (`[y/N]` via `src/delivery/cli/prompt.ts:promptLine()` or `--yes`; desktop checkbox, `looksLikeCloud` from `sync:status`); then current credential (passphrase or `--recovery-key` / the toggle) and the new passphrase twice.
2. `src/vault/application/use-cases/change-passphrase.use-case.ts:ChangePassphrase.execute()` — header → `src/vault/domain/services/folder-settlement.ts:refuseUnsettledFolder()` → `parsePassphrase` → `src/vault/application/services/resolve-unlock-key.ts:resolveUnlockKey()` + `src/vault/infra/file-vault-store.ts:FileVaultStore.readSchemaVersion()` (proves the key, read-only) → newer schema refused → new key = same salt/KDF, equal key → `PASSPHRASE_UNCHANGED` → cloud and not confirmed → `VAULT_FOLDER_UNSETTLED` (backstop).
3. `src/vault/infra/sqlite-vault-rekeyer.ts:SqliteVaultRekeyer.rekey()` — free space (3× db) → `openVaultDb` old key + `locking_mode = EXCLUSIVE` → lineage bump (own tx, old key) → `vault.db.pre-rekey.bak` + fsync → `cache_spill = OFF`, `PRAGMA rekey="x'<new key><current cipher_salt>'"` → release → verify with a fresh connection → delete backup. Failure: old key verifiably opens → `REKEY_FAILED`, else restore (delete `-journal`, rename backup over `vault.db`).
4. `ChangePassphrase.execute()` — `recordSeen(stamp)`, `setKey(new)` + `recordActivity`; `setKey` throws → `deleteKey`, `unlockedOnThisDevice: false`.
5. CLI prints the outcome (or the "LOCKED on this device" line) and `src/vault/infra/recovery-kit.ts:renderRecoveryKit()` with `issuedAt`; desktop puts the rendered kit in the one-shot slot, returns `{ vaultId, issuedAt, generation, unlockedOnThisDevice }`, and `desktop/src/renderer/app.tsx` `passphraseChanged` → `resetWorkspaceView()` → `desktop/src/renderer/state/session-state.ts:afterPassphraseChanged()` → `RecoveryKitScreen` → `afterKitAcknowledged(lockedAfterKit)`.
Side effects: `vault.db` re-encrypted in place (cipher salt kept), generation +1 with this device as writer, last-seen + activity, OS keychain holds the new key (or none). `vault.json` never written. No kit file.
Gotchas: deliberately outside `VaultSessions.withSession` (no idle guard, no migration; a behind schema is re-keyed as is). Raw-key `rekey="x'…'"` only — never `db.rekey()` / `hexrekey` (they treat the bytes as a passphrase). Every refusal must stay before the rekeyer (tests snapshot the files). The desktop copy for `VAULT_FOLDER_UNSETTLED` talks about leftover files, so surfaces gate the cloud confirmation themselves. Busy (another process holds the vault > 5 s) and low disk are `STORAGE_ERROR`. MCP and the SDK facade must never read `Container.changePassphrase` (D-N); the desktop response never carries `keyHex`.
