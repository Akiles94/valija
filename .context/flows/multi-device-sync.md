# Flow: multi-device-sync
Summary: vault in a synced folder → every committed write bumps an encrypted lineage stamp → unlock compares it with this device's last-seen → in-sync / fast-forward / fork notice; `sync:status` reports folder hazards.
Trigger: CLI `valija unlock|lock|status|doctor` (`src/delivery/cli/vault-commands.ts:unlockCommand()`); desktop `vault:unlock`, `vault:status`, `sync:status` (`desktop/src/main/ipc/handlers/vault-handlers.ts`, `desktop/src/main/ipc/handlers/sync-handlers.ts:createSyncHandlers()`).
Path:
1. `src/context/infra/vault-sessions.ts:SqliteVaultSessions.commitWrite()` — runs the mutation in a db transaction and `src/vault/infra/sqlite-lineage-store.ts:SqliteLineageStore.bump()` in the same tx (failed mutation → sentinel throw → rollback, no bump); after commit, `recordSeen()` for this device.
2. Only `session.write()` bumps: today `src/context/application/use-cases/save-context.use-case.ts` and `src/context/application/use-cases/import-items.use-case.ts:ImportItems.execute()` (one bump per import batch). Reads never bump.
3. Lineage = 4 rows in encrypted `meta` (`lineage_generation|stamp|writer|written_at`); random `src/vault/domain/values/write-stamp.ts:createWriteStamp()` per write.
4. `src/vault/application/use-cases/unlock-vault.use-case.ts:UnlockVault.execute()` — schema gate, then `src/vault/infra/file-vault-store.ts:FileVaultStore.readLineage()` (verifies key), then `src/vault/domain/services/vault-lineage.ts:classifyLineage()` vs `src/vault/infra/file-device-identity.ts:FileDeviceIdentity.lastSeen()`.
5. Fork → `VAULT_FORK_DETECTED` notice in the ok result (vault still unlocks, last-seen left untouched); CLI prints it to stderr, desktop maps it to `fork.noticeCode`.
6. `src/vault/infra/file-vault-folder.ts:FileVaultFolder.inspect()` — no decryption: sidecars, conflicted copies, `.pre-NNN.bak`, cloud-path hint; feeds `sync:status`, `LockVault`, `VaultStatus`, `src/delivery/diagnostics.ts:runDiagnostics()`.
Side effects: `meta` lineage rows; device-local `state.json` (deviceId, lastSeen*, lastActivityAt) under `src/shared/infra/state-paths.ts`, outside `VALIJA_HOME`, never synced.
Gotchas: fork is detected only in `UnlockVault`; `withSession` (MCP, imports) never classifies, and any later write on this device calls `recordSeen()`, silently clearing the pending fork warning. First bump yields generation 0 (`GENERATION_ZERO`); "never written" is `read() === null`, not generation 0. `readLineage()` runs `migrate()` as a side effect, so the upgrade-consent gate must precede it. Truncated/lost `state.json` mints a new deviceId and drops last-seen → a real fork reads as fast-forward (hence write-then-rename in `FileDeviceIdentity`). `journal_mode = DELETE`, not WAL (`src/shared/infra/sqlite.ts`), so only `vault.db` syncs at rest. OneDrive conflict copies are not detected.
