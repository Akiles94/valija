# Gotchas
## Repo-wide
- Every vault mutation runs inside `session.write()` (`src/context/infra/vault-sessions.ts:SqliteVaultSessions.commitWrite()`): mutation + lineage `bump` in one transaction, `recordSeen` only after commit. A write outside it compiles and passes unit tests, but other devices never see a new generation and fork detection (`src/vault/domain/services/vault-lineage.ts:classifyLineage()`) goes blind. Today only `src/context/application/use-cases/save-context.use-case.ts:SaveContext.execute()` and `src/context/application/use-cases/import-items.use-case.ts` write.
- Implementation edits (`src/**`, `desktop/**`, `tools/**`, `package.json`, `tsconfig*.json`, `tsup.config.ts`) are blocked until the current advance's `plan.md` has an `Approved:` line, which only Oscar authorizes (`.claude/hooks/guard-implementation.sh`, rules in `CLAUDE.md`, fast-track included). "Current" = `$VALIJA_ADVANCE`, else the most recently modified `advances/*/plan.md`, so touching an old advance's plan silently moves the gate. Push/merge also need `Verdict: PASS` in `review.md` (`.claude/hooks/guard-git-ops.sh`).
- `docs/guide/**` is generated (`package.json#scripts.docs`); never hand-edit it. `package.json#scripts.docs:check` (CI) fails when an export lacks real TSDoc, when a new CLI command / MCP tool / IPC channel / use case / error code is not cited by a `docs/flows/*.md` flow, or when a CLI command or desktop channel has no counterpart and no entry in `tools/living-docs/valija/composition/valija-guide.ts:VALIJA_PARITY` (CLI↔desktop parity rule). Details: `CONTRIBUTING.md`.
- Several tests scan source text, comments included: `desktop/src/shared/i18n/error-copy.test.ts` parses each `src/*/domain/errors.ts` `*ErrorCode` union up to the first `;`, so a `;` or a double-quoted UPPER_CASE word in an error-code doc comment truncates or invents codes; `desktop/src/main/infra/no-network-surface.test.ts` forbids URLs, `fetch(`, `setInterval`, `crashReporter` anywhere in `desktop/src`. Evidence: tripwire table in `advances/LIVING-DOCS/plan.md`.
- Root `npm run test` covers only `src/**` and `tools/**` (`vitest.config.ts`); desktop tests that guard root code (error copy, dependency parity, import no-reimplementation) run only via `cd desktop && npm run test`. Run both after touching `src/*/domain/errors.ts` or root dependencies.
## By area
### vault / storage
- Unlock must gate before migrating: `src/vault/infra/file-vault-store.ts:FileVaultStore.readSchemaVersion()` stays non-migrating, `FileVaultStore.readLineage()` migrates as a side effect, so `src/vault/application/use-cases/unlock-vault.use-case.ts:UnlockVault.execute()` returns `VAULT_UPGRADE_REQUIRED` unless `upgradeConfirmed` (CLI always passes true; desktop shows `src/shared/infra/migrations.ts:pendingMigrations()` first). Reordering silently upgrades without confirmation. On a fork it deliberately skips `recordSeen` so the warning persists until resolved.
- Schema change = new file in `src/shared/infra/migrations/` + entry in `MIGRATIONS` (`src/shared/infra/migrations.ts`); table-rebuild migrations set `backup: true` (ciphertext backup, kept on failure). `LATEST_SCHEMA_VERSION` derives from that list.
- Journal mode is `DELETE`, never WAL (`src/shared/infra/sqlite.ts:openVaultDb()`): a synced folder must only see `vault.db` at rest; sidecars (`-wal`, `-shm`, `-journal`) risk sync clients copying a torn vault. Related: `2fcf51f` (lock must not claim "safe" while sidecars exist). `openVaultDb` also deletes a cold leftover `-journal` (a process killed in `locking_mode = EXCLUSIVE`, e.g. a crashed rekey) via a `journal_mode = PERSIST` → `DELETE` toggle after its first read; never delete a `-journal` by hand before an open has rolled a hot one back.
- Device-local state (device id, last-seen lineage, last activity) lives under `VALIJA_STATE_HOME` (`src/shared/infra/state-paths.ts:resolveStatePaths()`), deliberately not under `VALIJA_HOME`, which may be a synced folder. Putting it in the vault folder makes devices share an identity.
- "Unlocked" = key in the OS keychain; idle auto-lock is lazy, checked only at session open (`src/vault/application/policies/session-guard.ts:SessionGuard.guard()`), and a wrong key deletes the keychain entry (`SqliteVaultSessions.openRepositories()`). A new entry point that opens the DB outside `VaultSessions.withSession` bypasses both.
- Relocation: vault must be locked (never handles the key), copy → verify → only then delete source; client configs are re-pointed afterwards by `desktop/src/main/ipc/handlers/relocation-handlers.ts`, never by the use case (`src/vault/application/use-cases/relocate-vault.use-case.ts:RelocateVault`). Path checks follow the injected platform, not the host OS (`src/vault/domain/services/vault-relocation.ts`, fix `8fd3bd9`).
### context / importers
- `imported` is storable but never saveable: `ITEM_TYPES` (save, MCP) excludes it, `STORABLE_ITEM_TYPES` includes it (`src/context/domain/values/item-type.ts`). Adding it to `ITEM_TYPES` lets a model mint fake imports.
- Imported item ids are a hash of project, source, conversation id and chunk index (`src/context/domain/entities/context-item.ts:importedItemId()`); re-import upserts only while those stay stable. Changing chunking or the hash input duplicates history.
- `generic` must stay out of `autodetect` (`src/importers/infra/parser-registry.ts:parserRegistry`): its permissive match would swallow malformed official exports.
- Pack, export and search output are pinned by the golden vault (`src/delivery/vault-format-conformance.test.ts`). Intentional changes: regenerate with `VALIJA_WRITE_GOLDEN_VAULT=1`, review the diff, update `docs/vault-format.md`.
### desktop
- IPC errors carry only `code` (`desktop/src/main/ipc/to-ipc-result.ts:toIpcResult()`); the renderer maps codes to i18n copy. File and folder paths never cross IPC: pickers return opaque handles resolved in main (`desktop/src/main/infra/electron-file-picker.ts:ElectronFilePicker.resolveHandle()`), and `preferences:write` has no `vaultPath`. The recovery kit is handed over once (`vault:readRecoveryKit` clears it in `desktop/src/main/ipc/handlers/vault-handlers.ts`).
- New channel = `desktop/src/shared/ipc/channels.ts` + zod schema in `desktop/src/main/ipc/schemas.ts` + handler (else `desktop/src/main/ipc/register-handlers.ts:registerHandlers()` throws at startup) + a hand-written method in `desktop/src/preload/index.ts` (never a loop) + `desktop/src/renderer/state/bridge.ts:ValijaBridge`; screens use the bridge, never `window.valija`.
- Desktop main imports root `src/` directly and reuses root use cases via the container; it must not reimplement parsers or repositories (`desktop/src/main/ipc/handlers/import-no-reimplementation.test.ts`). Shared native deps are pinned identically in both `package.json` files (`desktop/src/main/infra/dependency-parity.test.ts`); CI installs root deps first (`cb6145f`).
- Every transition out of "unlocked" must also call `desktop/src/renderer/state/workspace-nav.ts:resetWorkspaceView()`, else the next unlock reopens the relocation wizard. Evidence: `200f432` (C2), `desktop/src/renderer/app.tsx`.
### delivery / living-docs
- `src/delivery/cli/build-program.ts:buildProgram()` and `src/delivery/mcp/server.ts:buildMcpServer()` may read the container only inside actions/handlers: living-docs introspects them with a throwing proxy (`tools/living-docs/valija/surfaces/inert-container.ts:createInertContainer()`), so a build-time container access breaks `docs:check`.
